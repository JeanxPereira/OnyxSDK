# tools

`check.py` is the single build verdict. It runs configure, build, ctest and lint in order, prints one `ok`/`FAIL` line per step with elapsed seconds, stops at the first failing step and exits with that step's exit code. Flags: `--preset P` (default `windows-debug` on Windows, `linux-debug` elsewhere), `--no-build`, `--no-test`, `--lint-only`, `--ctest-regex R`, `--jobs N`. `--ctest-regex` takes the regex as one argument, so `--ctest-regex "Core|Cli"` works on Windows too: the wrapper quotes every argument that `cmd` would otherwise split. `--jobs N` (default: the CPU count) is passed to the build as `--parallel N`; lower it on a machine short of memory. A ctest run that finds no tests is a failure. Release presets have no test preset, so ctest runs with `--test-dir build/<preset>`.

On Windows MSVC is not on `PATH`, so `check.py` locates the newest Visual Studio with the C++ workload through `vswhere.exe`, writes a temporary `.bat` that calls `vcvars64.bat`, and runs every cmake and ctest command inside it. On other systems the commands run directly.

`lint.py [root]` checks layer hygiene and prints `path:line: rule: detail`, exiting 1 on any hit. Rules: forbidden includes per layer, singleton accessors (`static T& Get()`/`Instance()`), game names under `Source/`, `Examples/` and `Tests/` (except `Tests/Golden/`), public headers without `#pragma once`, and project-history wording in comments under `Source/`. `legacy/`, `third_party/`, `build/` and `.superpowers/` are skipped. `lint_test.py` is its self-test and prints `ok 5`; the lint step of `check.py` runs both and fails unless the self-test prints it.

GPU tests. `Gpu.Unit`, `Render.Unit`, `TestKit.Unit` and `Oracle.Unit` need no device. `Gpu.Device`, `Render.Gpu`, `Render.Parity` and `Render.Reproducible` (the last two drive the `OnyxOracle` tool in `Tests/Oracle`) need a Vulkan device and exit 77 when none exists, which ctest reports as SKIP through `SKIP_RETURN_CODE 77`; ctest does not count a SKIP as a failure, and `check.py`'s `--no-tests=error` only rejects a run that finds no tests. Hosted Windows runners have no Vulkan ICD and skip every device suite; the Linux job installs `mesa-vulkan-drivers`, whose lavapipe is a CPU device, so they run there. Shaders compile to SPIR-V at build time: the build looks for `glslang` or `glslangValidator` first (`find_program` with hints `$ENV{VULKAN_SDK}/Bin` and `$ENV{VULKAN_SDK}/bin`) and falls back to fetching glslang 14.3.0 and building `glslang-standalone`. Tolerance profiles live in `Tests/Golden/tolerances.toml`: `[hardware]`, and `[software]` for lavapipe once recorded; `Render.Parity` picks `software` when the device type is CPU. Run the parity gate alone with `py -3 tools/check.py --preset windows-debug --ctest-regex "Render.Parity"`.
