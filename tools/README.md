# tools

`check.py` is the single build verdict. It runs configure, build, ctest and lint in order, prints one `ok`/`FAIL` line per step with elapsed seconds, stops at the first failing step and exits with that step's exit code. Flags: `--preset P` (default `windows-debug` on Windows, `linux-debug` elsewhere), `--no-build`, `--no-test`, `--lint-only`, `--ctest-regex R`, `--jobs N`. `--ctest-regex` takes the regex as one argument, so `--ctest-regex "Core|Cli"` works on Windows too: the wrapper quotes every argument that `cmd` would otherwise split. `--jobs N` (default: the CPU count) is passed to the build as `--parallel N`; lower it on a machine short of memory. A ctest run that finds no tests is a failure. Release presets have no test preset, so ctest runs with `--test-dir build/<preset>`.

On Windows MSVC is not on `PATH`, so `check.py` locates the newest Visual Studio with the C++ workload through `vswhere.exe`, writes a temporary `.bat` that calls `vcvars64.bat`, and runs every cmake and ctest command inside it. On other systems the commands run directly.

`lint.py [root]` checks layer hygiene and prints `path:line: rule: detail`, exiting 1 on any hit. Rules: forbidden includes per layer, singleton accessors (`static T& Get()`/`Instance()`), game names under `Source/`, `Examples/` and `Tests/` (except `Tests/Golden/`), public headers without `#pragma once`, project-history wording in comments under `Source/`, and writes to `GetStyle().Colors[` / `style.Colors[` under `Source/Ui` and `Source/Shell` outside `Source/Ui/Theme.cpp`. `legacy/`, `third_party/`, `build/` and `.superpowers/` are skipped. `lint_test.py` is its self-test and prints `ok 6`; the lint step of `check.py` runs both and fails unless the self-test prints it.

Ui and Shell suites. `Ui.Unit` and `Shell.Unit` need no device. `Ui.Gpu` exits 77 without a Vulkan device and runs on lavapipe. `Shell.Window` opens a hidden window through `Shell::Step` and exits 77 without GLFW or a present-capable device. `Examples.Build` runs `MinimalViewer --help` through `CheckHelp.cmake`, requires exit 0 and the usage text, and never skips. `Examples.Embedded` runs `Embedded --frames 3` and exits 77 without a device. Hosted runners have no display, so `Shell.Window` and `Examples.Embedded` report SKIP there.

Linux packages. Besides the toolchain (`clang ninja-build glslang-tools libvulkan-dev mesa-vulkan-drivers vulkan-validationlayers`), GLFW builds from source and needs `libxkbcommon-dev libwayland-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libgl-dev`; `libglfw3-dev` is not needed.

GPU tests. `Gpu.Unit`, `Render.Unit`, `TestKit.Unit` and `Oracle.Unit` need no device. `Gpu.Device`, `Render.Gpu`, `Render.Parity` and `Render.Reproducible` (the last two drive the `OnyxOracle` tool in `Tests/Oracle`) need a Vulkan device and exit 77 when none exists, which ctest reports as SKIP through `SKIP_RETURN_CODE 77`; ctest does not count a SKIP as a failure, and `check.py`'s `--no-tests=error` only rejects a run that finds no tests. Hosted Windows runners have no Vulkan ICD and skip every device suite; the Linux job installs `mesa-vulkan-drivers`, whose lavapipe is a CPU device, so they run there. Shaders compile to SPIR-V at build time: the build looks for `glslang` or `glslangValidator` first (`find_program` with hints `$ENV{VULKAN_SDK}/Bin` and `$ENV{VULKAN_SDK}/bin`) and falls back to fetching glslang 14.3.0 and building `glslang-standalone`. Tolerance profiles live in `Tests/Golden/tolerances.toml`: `[hardware]`, and `[software]` for lavapipe; `Render.Parity` picks `software` when the device type is CPU. The `[software]` values were measured on WSL Mesa 25.2.8 / LLVM 20.1.2; the first hosted Linux run is a measurement event and may need the profile re-recorded with `OnyxOracle parity --diff`. Run the parity gate alone with `py -3 tools/check.py --preset windows-debug --ctest-regex "Render.Parity"`.

Validation. The GPU suites require the Khronos validation layer: a device created with validation but without `VK_LAYER_KHRONOS_validation` fails the test instead of passing every "zero validation messages" check vacuously. Set `ONYX_NO_VALIDATION=1` to opt out where the layer is not installed (WSL, for example); each executable then prints one message saying its validation checks are vacuous. The Linux CI job installs `vulkan-validationlayers` and does not set it.

The oracle never writes over PNGs it did not produce: `render`, `parity` and `reproducible` refuse (exit 64) an `--out` directory that already holds a corpus PNG without the `.OnyxOracleOutput` marker the oracle writes into its own output directories, and `render` and `reproducible` take an optional `--golden DIR` that must differ from `--out`. An output directory left by an older build (PNGs, no marker) has to be deleted once.

Media. `Onyx::Media` needs FFmpeg. On Windows the configure downloads a pinned prebuilt archive (`ONYX_FFMPEG_WIN_URL`) and `onyx_install_media_runtime` copies its DLLs next to every executable that links Media. The archive is the LGPL shared build from BtbN, not the GPL one: Onyx is MIT and redistributes those DLLs, which the LGPL allows for dynamically linked libraries. On Linux it needs `libavformat-dev libavcodec-dev libavutil-dev libswscale-dev libswresample-dev pkg-config`. A missing FFmpeg is a configure error. Where the dev packages cannot be installed (WSL, for example) configure with `-DONYX_WITH_MEDIA=OFF`, which fetches no FFmpeg. `Media.Unit` needs no device and no display; `Media.Gpu` exits 77 without a Vulkan device.

`readme_assets.py` redraws the README figures and badges into `docs/assets/` (banner, section headers, the layer stack, the file-to-view flow, the host snippet, one badge per stack fact) in one skin, with the lettering converted to paths; it needs fontTools and a monospace TrueType font on the machine. The SVGs are committed, so readers need nothing.
